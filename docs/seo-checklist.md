# Обязательный SEO-чек-лист и таблицы казино

Версия требований: `owner-seo-2026-09-06-v1`. Все 58 строк пользователя, включая повторяющиеся требования, имеют отдельные ID SEO-01…SEO-58 в `drop_restorer/core/seo_contract.py`.

## Порядок работы

Скачивание → просмотр страниц и метаданных → подготовка меню и URL → SEO-чек-лист → решение владельца → создание темы/WXR → просмотр результата → отдельное одобрение ZIP.

До решения по чек-листу существуют страницы, ресурсы и отчёты; экспорт WordPress ещё не создаётся. Старую готовую сборку можно перевести на новый этап отдельной копией без повторной загрузки архива. Исходная сборка сохраняется.

Автоматически проверяются локальные HTTP-ответы, альтернативные URL, ссылки, robots/sitemap, canonical, количество и уникальность метатегов, H1, lang/og:locale, наличие контента/ресурсов и меню. Настоящий Chromium открывает **каждую** страницу на 1920×1080, 768×1024, 375×812, нажимает мобильное меню, измеряет выход за экран, проверяет изображения и читаемость по техническим признакам, сохраняет снимки. При ошибке браузера отсутствие доказательств остаётся в отчёте; владелец может одобрить продолжение с этим результатом.

Смысл заголовков, текста и описаний, GEO, внешний вид, допустимость организаций, марок, ФИО и контактов требуют просмотра владельцем. Найденные строки — кандидаты, а не достоверное распознавание всех сущностей. Они не удаляются без разбора. Агент анализирует выбранный сайт только по кнопке, его замечания не превращаются в автоматически пройденные пункты. Расход учитывается журналом сборки.

Статусы: автоматически пройдено / подтверждено владельцем / ошибка / требуется просмотр / ещё не проверено / отложено до заполнения казино. Одобрение всей сборки не меняет автоматические ошибки и неизвестные результаты на «Пройдено». Кнопка «Одобрить сайт — создать тему» сохраняет отдельное решение владельца с текущей версией, временем и списком незакрытых пунктов; подключение агента и поштучное подтверждение 58 строк не требуются. В финальном превью «Одобрить и упаковать» также принимает оставшиеся замечания и сохраняет их в ZIP. Без явного одобрения автоматический переход по-прежнему требует завершённого чек-листа. Изменение страницы, ресурса, URL, таблицы или шаблона отменяет доказательства и решения для предыдущей версии. Перед темой и ZIP отчёт пересчитывается по текущим данным.

Можно выбрать URL со слешем или без. Для выбранных страниц формируются 301 с альтернативного окончания, index.php/index.html и параметров. Если исходный архив содержит несколько страниц с параметрами, задайте каждой понятный уникальный путь в URL-плане. Служебные пути и совпадающие адреса запрещены.

## Казино заполняет владелец

Canonical и оболочка с одним H1 создаются инструментом. Gutenberg-контент, Title и Description казино остаются пустыми до заполнения владельцем, но сами страницы сразу остаются индексируемыми и включаются в sitemap. Отсутствие заполнения отображается отдельным замечанием чек-листа и не закрывается автоматически.

В WordPress заполните текст и уникальные Title/Description, добавьте таблицу и проверьте бренды. Пустой текст, отсутствие метаданных, второй H1 или неподтверждённые предложения остаются замечаниями до исправления; инструмент не добавляет noindex к созданным страницам. При работе с SEO-плагином требуется отдельная проверка его фактического вывода; локальный отчёт не заменяет финальный аудит установленного сайта. Системную настройку WordPress «Попросить поисковые системы не индексировать сайт» проверьте отдельно.

## Шорткод

В блоке WordPress «Шорткод» вставьте:

```text
[casino_table id="88"]
```

Для другого GEO меняйте ID. Чтобы задать компактную высоту каждого предложения, используйте, например:

```text
[casino_table id="88" row_height="110"]
```

`row_height` — необязательное целое число от 72 до 240 пикселей. Параметр влияет только на вертикальный размер: ширина остаётся адаптивной, а строка может вырасти, если содержимое не помещается. Без параметра действует глобальная высота из настроек сборки. Общая ширина казино-контента, таблицы, пяти колонок и отступы ячеек задаются в форме «Размеры страниц казино и таблиц» на этапе метаданных; 0 у ширины означает всю доступную ширину. Совместимый синоним: `[hds_table id="88" row_height="110"]`. Несколько таблиц на одной странице получают разные DOM ID. Шорткод действует на казино-страницах созданной темы.

Начиная с темы 0.1.9 значение `row_height` записывается только в оболочку конкретного экземпляра таблицы. Оно не меняет другие таблицы на странице; новая версия CSS подключается с версией темы, поэтому обновлённая высота не остаётся скрытой старым кешем браузера.

Тема получает HTML таблицы с фиксированного `cryptocasinokingdom.com` на сервере, сохраняет бренды и исходные адреса, удаляет исполняемые вставки и заменяет ссылки **до** вывода таблицы. Оригинальный браузерный загрузчик не запускается, его cookie не определяют направление перехода. Требуются исходящие HTTPS-запросы к провайдеру и PHP DOM/XML. Данные обновляются каждые 15 минут; ответы с ошибками не выдаются за успешную загрузку.

В теме 0.1.4 исправлен вывод CSS поставщика обычным текстом над таблицей. Блоки style удаляются вместе с содержимым до очистки WordPress, оформление загружается отдельными таблицами стилей. HTML-фрагменты section с BOM разбираются внутри явного body; это проверяется на настоящем ответе таблицы 88. Версия кеша виджета изменена, поэтому после обновления не используется прежний некорректный HTML. Идентификаторы предложений, партнёрские параметры и подтверждения владельца при этом сохраняются.

Начиная с темы 0.1.5 публичный формат ссылок: **`/go/brand`**, без query-параметров и фрагментов. ID предложения остаётся внутренним ключом реестра. Сервер выбирает точное сохранённое предложение по бренду и странице перехода из same-origin Referer; cookie и номер оффера в URL не участвуют. Для прямого открытия работает единственное назначение либо детерминированный выбор того же предложения gmbl.guru, если варианты различаются только параметром страницы pg. Сам адрес назначения не переписывается. Если для одного бренда на одной странице есть разные предложения или без контекста остаются разные кампании, возвращается 404 и проверка показывает конфликт. Нельзя разместить две разные кампании одного бренда на одной странице под одинаковым коротким адресом.

Логотип и кнопка карточки привязаны к одному предложению. Назначение хранится на сервере: HTTPS, без локальных адресов, учётных данных и управляющих символов. Входящие cookie, `url` и другие параметры не заменяют назначение. Переход — 302, noindex и без кеширования. Варианты действующего маршрута со слешем или параметрами, включая прежний offer, получают 301 на `/go/brand`. Неизвестный бренд, неоднозначная или устаревшая запись возвращают 404. После обновления таблицы прежние назначения этой таблицы/страницы заменяются новым снимком. Чек-лист проверяет отсутствие параметров в настоящем HTML и точное совпадение Location с назначением для каждой исходной страницы; конфликт запрещает подтверждение бренда и SEO-допуск WordPress.

## Проверка партнёрских ссылок

В локальном чек-листе нажмите «Загрузить и сверить таблицы», указав ID. На установленном сайте используйте «Внешний вид → Партнёрские ссылки».

Для каждого предложения доступны бренд, алиас, страница, ID таблицы, исходный URL, параметры (включая повторные ключи), контекст таблицы dept/st/p/sfx. URL не перекодируется и не дополняется предположительными значениями. Пропущенные или конфликтующие параметры таблицы блокируют подтверждение.

Для фактического формата `gmbl.guru/lldrp` проверяются соответствия dept→d, p→pr и st без учёта регистра, а также br→бренд, s→домен, pg→страница и наличие net/g. Это сопоставление не меняет сам URL. Провайдер требует браузерно-совместимый User-Agent: запросы Python/WordPress без него могут получать HTTP 520. Оба загрузчика используют `Mozilla/5.0 (compatible; DropRestorer/1.0)` и параметр cb, как штатный виджет. Проверка этой регрессии включена в тесты. В локальном превью CSS, изображения и импортируемые шрифты таблицы сохраняются локально; folders/offer-wall получают соответствующие стили.

«Проверить переходы» записывает каждый HTTP-переход и конечный URL. Затем владелец подтверждает, что конечная страница принадлежит указанному бренду и соответствует партнёрскому предложению. HTTP 200 означает доступность, но не подтверждает бренд; защитная страница также может отвечать 200. Ошибки доступа, GEO-блокировка, JavaScript-переходы и недоступность провайдера остаются непроверенными. Инструмент не может доказать регистрацию конверсии в кабинете партнёрской программы без данных этой программы.

## Отчёт и проверка после установки

Начиная с темы 0.1.3, основной адрес берётся из настройки WordPress «Адрес сайта». Этот адрес используется для редиректов, canonical, robots/sitemap и контекста партнёрских таблиц. Старые HTTP/www-значения архива не возвращают установленный HTTPS-сайт на другой адрес. Локальное превью сохраняет выбранный публичный canonical. Установка рассчитана на корень домена; настройки HTTPS за обратным прокси остаются ответственностью конфигурации WordPress/хостинга.

Регрессионная проверка запускает настоящий WordPress с публичными значениями Host и HTTPS при локальном соединении: HTTP/HTTPS, www/apex, альтернативные пути, три казино-страницы с таблицей, robots/sitemap и точные /go/ переходы. Прежний код воспроизводит обратный переход на HTTP; при принудительном HTTPS на хостинге это цикл. Ответы поставщика 301 и 520 проверяются отдельно: сообщение внутри статьи, HTTP 200 самой страницы, без Location. Отдельный запуск `python -m tests_drop_restorer.wordpress_redirect_qa` также проверяет настоящую таблицу 88 на трёх страницах в изолированном WordPress. Конечный внешний сайт партнёра при этом не объявляется проверенным.

`seo-checklist.json`: все требования, доказательства по URL, решения и отпечаток проверенной версии. `checks_passed` отражает результаты проверок; `can_build` также учитывает явное одобрение владельца. `owner-approvals.json` в ZIP сохраняет решения перед темой и упаковкой, включая принятые замечания. Одобрение не заменяет финальную проверку установленного WordPress и его SEO-плагинов; готовые страницы остаются открытыми для индексации. `visual-checks.json` и `checklist-screenshots/`: результаты браузера. `affiliate-manifest.json`: полученные таблицы, точные адреса и цепочки. Эти файлы доступны в панели.

Локальный отчёт подтверждает подготовленный сайт. До открытия публичной индексации нужно повторить проверки на установленном WordPress: HTTPS/TLS, http→https, www/apex, реальные robots/sitemap, ответы веб-сервера и поведение SEO/кеширующих плагинов. Локальная проверка не может подтвердить ещё не установленный публичный сервер; поле `ready_for_public_indexing` остаётся false. Партнёрские таблицы иных форматов и их дополнительные интерактивные элементы требуют проверки на реальных данных провайдера.

Разработческие тесты используют искусственные страницы и предложения, отдельно помечены как fixture и не являются одобрением реального сайта.
